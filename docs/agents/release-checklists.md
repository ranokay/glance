# Release checklists

Step-by-step bump procedures. `scripts/check-release-metadata.sh` is the
machine-readable mirror of the version checklist — update its literals in the
same commit as any intentional bump, then run it.

## Sparkle prerequisites (one-time, before the first v1.8 release)

1. EdDSA update-signing key: run `bin/generate_keys` from the Sparkle 2.10
   release tools locally (private key lives in the login Keychain; public key
   is already in `Glance/Info.plist` as `SUPublicEDKey` — never regenerate, or
   existing installs can no longer validate any update).
2. Export the private key with `bin/generate_keys -x <file>` and add its
   contents as the `SPARKLE_EDDSA_PRIVATE_KEY` repository secret. Leaving the
   secret unset skips appcast generation (release still publishes the DMG).
3. The update feed is a **release asset**: each release publishes its own
   `appcast.xml` (generated by CI from the published ZIP's bytes), and apps
   read the stable redirect
   `https://github.com/ranokay/glance/releases/latest/download/appcast.xml`
   — no branch is ever written by a release. `main` mirrors upstream
   `chamburr/glance` and is never written to at all; `develop` is the only
   working branch. Verify the new release's appcast asset looks sane.

## Version bump (1.9.0 build 27 → next)

1. `Glance.xcodeproj/project.pbxproj`: `MARKETING_VERSION` (×4: app + plugin ×
   Debug/Release) and `CURRENT_PROJECT_VERSION` (×4, same scopes). The app
   `Info.plist` follows via `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)`.
2. `README.md`: hero line and requirements line (`Version X.Y.Z (build N)`).
3. `AppStore/Listing/Description.txt`: version line.
4. `CHANGELOG.md`: new entry on top, append-only, never rewrite history. Keep
   it short: `# Glance X.Y.Z`, a one-sentence intro, then at most a handful of
   bullets covering the user-visible changes. Add `##` group headings only when
   a release spans several unrelated areas. Do not add a signing,
   notarization, or platform footer — that caveat lives in `README.md`.
5. `scripts/check-release-metadata.sh`: version/build literals and occurrence
   counts; run the script.
6. Tag `vX.Y.Z` and push the tag — `release.yaml` extracts that version's
   section from `CHANGELOG.md`, appends a `**Full Changelog**` compare link to
   the previous release, builds the DMG, and creates the GitHub release with
   the result as its notes.

## Type add (new extension or new preview kind)

1. `QLPlugin/Info.plist` `QLSupportedContentTypes`: the file's UTI.
2. `Glance/Shared/Utils/SupportedPreviewRegistry.swift`: `extensionEntry`
   (plus a new `PreviewFileType` case when it is a new kind, not just a new
   extension of an existing one).
3. `Glance/Shared/Utils/PreviewVCFactory.swift`: switch arm mapping the new
   `PreviewFileType` to its `Preview` class (new kinds only).
4. Tests: extend the `PreviewFactoryTests` case table, add a smoke test, and
   drop a fixture in `GlanceTests/TestFiles` — the corpus sweep then covers
   the new type automatically.
5. Docs: extend the supported-types list in `AppStore/Listing/Description.txt`
   when the type is user-facing.

## App icon edit (`Glance/Glance.icon`)

1. `Glance/Glance.icon` is the editable Icon Composer document. Its layers are
   plain white SVG discs; colour and glass come from `icon.json`
   fill/glass specializations, so edit colours there, not in the SVGs.
2. Re-render the README hero from the document, then flatten it to 8-bit and
   commit it as `AppStore/Assets/AppIcon.png`:

   ```sh
   "/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables/ictool" \
     Glance/Glance.icon --export-image --platform macOS --rendition Default \
     --width 512 --height 512 --scale 1 --output-file /tmp/AppIcon.png
   ```
3. `Glance/Utils/StatusItemMark.swift` is the menu-bar reduction of the same
   mark; re-check it at 18 pt on light, dark, and tinted menu bars whenever the
   silhouette changes.

## Web-runtime bump (drawio, Pele/Mermaid diagrams, or similar bundled viewer)

1. `docs/<name>-runtime.md`: new version, source URL, SHA-256 digest of the
   runtime and of its license file, measured Release size impact
   (`Glance.app` and `QLPlugin.appex` before/after), and any CSP changes.
2. `PreviewCore/THIRD_PARTY_LICENSES.md`: refresh the license table from
   `PreviewCore/Cargo.lock` (authoritative) when Rust dependencies move with
   the bump.
3. Run the full `mise run verify` — runtime swaps must survive the DOM,
   color-scheme, and corpus gates.
